01GNC / AUTONOMY

Separation of tasks: estimate, decision, control

The central design choice is to separate the physical state, the onboard estimate, and the supervisory decision. Each has a different job and can access different information. Such the whole system is protected to be corrupted by a fausse readings from a sensor.

Sense & estimate
Own position and attitude identification requires information from sensors. Gyroscope and attitude-sensor measurements feed a multiplicative extended Kalman filter (MEKF). Each sensor provide measurements with its own frequency, replay approach with fixed-lag permits incorporate delayed observations at their measurement time.
Guide & command
A satellite has to accolplish a mission. A guidance abstraction has to produces attitude and rate references for each mission, mission manager has to oreder in-missopn priorities, control provides exact commands to a plant. e.g. in the ground-pass scenario, the learned policy issues four wheel-motor commands from tracking errors and estimated wheel authority.
Detect & supervise
Detect a possibility of a fault, evaluate it and deal with it. Fault detection estimates available wheel authority from telemetry. Supervisory logic can change operating modes or override the target. An agent operates on the lowest lever - control the motors, all abstractions above implemented independently, an agent doesn't have truth information about control over wheels degradation or loss.

Reaction wheels have a major physical limitation: momentum saturation. A reaction wheel can store only a limited amount of angular momentum before reaching its maximum rotational speed. Over time, external disturbances and the satellite’s operational tasks can cause the wheels to spin progressively faster as they compensate for accumulated angular momentum. Eventually, a wheel may reach its maximum RPM and lose the ability to provide additional control torque in the required direction. To prevent this, operators perform momentum dumping, or desaturation, by applying an external torque that allows reaction wheels to remove angular momentum by slowing down. In low Earth orbit, magnetorquers can interact with Earth’s magnetic field to generate this external torque, enabling the reaction wheels to shed accumulated momentum and return to their normal operating range.

02ML / RL

A small policy with a specific task

An agent is trained with proximal policy optimization PPO algorithm. An approximator is a tiny two layers NN with tanh activation function. Whatever happens an agent provides commands for each of 4 reaction wheels. The approximator paramenters are adjusted to provide an adequate torque given the observation vector. However an agent only control the motors, mission guidance, supervision, fault detection, signal estimation implemented as separate layers.

25 inputs→128 × 128 activation→4 commands

The observation contains attitude-error, rate-error vectors, four measured wheel speeds, four previous actions, four estimated wheel-authority values, an estimator confidence value and 6 supervisory mode values. The actor has 20,356 parameters that is relatively small to be optimized for an embedded solution. The critic is separate and not user at inference time.

How the learning problem evolved

The project explores corrections to a conventional proportional–derivative (PD) controller, then direct body-torque commands, then direct wheel-motor commands. These move more responsibility into the policy. An agent operate above a PD controller, however in the scope of this project a deliberate choise was to use PD imitation as a training tool.

03SOFTWARE / EMBEDDED

Make timing and interfaces explicit

Since the beginning of the project the simulation transformed from pure math based closer to the Hardware-In-The-Loop. In the current implementation the physics advances at 100 Hz and control at 20 Hz. Sensors have different delivery rates and latencies. The policy runs against delivered information rather than a simultaneous snapshot of the simulated plant.

Current implementation includes explicit sensor, navigation, reference, and actuator messages, with a flight-style scheduler. This creates a boundary between the controller and the simulator, so each can be exercised separately.

A small network makes deployment a question worth measuring. Target-processor latency, memory use, numerical precision, and deadline behavior still require measurements

04VALIDATION / INFERENCE

Demonstration of agent capabilities

Currently, the agent is evaluated across six scenarios, each described in detail on a separate page. Since every milestone introduces substantial changes to the operating conditions, a model trained for a previous milestone is usually no longer able to perform optimally and therefore requires retraining or fine-tuning. For this reason, optimization for embedded inference is developed as a parallel track rather than as part of the main training workflow. Transferring an already optimized model to a new milestone is even more challenging than adapting the original model, so embedded deployment requires its own dedicated optimization process.

Parameters optimization
The neural network parameters were optimized using quantization techniques. Because the network is already relatively small, there is limited room for further optimization, and pruning is not particularly suitable for the same reason.
Embedded inference
On the other hand, the compact size of the approximator makes it a promising candidate for implementing the agent directly in Rust using matrix multiplication operations.
Independent check
Upcomming implementation includes an initial open-loop Basilisk interface harness. Numerical execution and independent closed-loop validation remain to be completed.

Scope: simulation research. Hardware transfer and flight qualification have not been demonstrated.

↳PROJECT HISTORY

Each milestone changes the problem.

  1. Foundation

    Learning with a conventional controller

    Rigid-body attitude dynamics, a PD reference controller, residual actions, and imitation learning establish a starting point.

  2. A1

    Delivered telemetry

    Gyroscope and wheel-speed samples acquire delivery timing. Attitude-error inputs still use simulator truth at this stage.

  3. A2

    Orbital context

    Orbit and sensor models add star, magnetic-field, Sun, and GNSS measurements. Generating them precedes using them for policy state estimation.

  4. A3

    Knowing the attitude

    The MEKF estimates attitude and gyro bias. Acquisition behavior becomes part of the control problem; initial delay compensation is still approximate.

  5. B1

    Closing the model gaps

    Fixed-lag measurement replay and actuator nonidealities replace earlier approximations.

  6. B2

    Fault-aware operation

    Telemetry-derived wheel authority and supervisory decisions replace privileged knowledge of injected faults.

  7. B3

    Ground-pass tracking

    Persistent mission phases, continuous references, windowed authority estimation, and magnetic momentum management connect control to a mission.

  8. C1 · ongoing

    Independent verification

    Explicit flight-style interfaces and an initial open-loop Basilisk harness establish the next validation boundary. Numerical validation remains pending.
